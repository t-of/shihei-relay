# 紙幣リレー — 記番号でお札の行方をたどる

財布のお札の記番号を撮るか打つかして、いる市区町村と登録する。同じお札を誰かが登録していたら、
どこから何 km・何時間で来たかが分かる。ゾロ目やキリ番など、レア番号の判定つき。
米国の Where's George?（1998〜）の日本円版。

## 🔗 リンク

- 遊ぶ: （Cloudflare への公開後にここへ URL を書く）
- 制作: [T.OF...](https://t-of.github.io/)

## 遊び方

1. 財布からお札を 1 枚。左上か右下の英字と数字（記番号）を **カメラで撮る** か、専用のキーパッドで打つ。
2. 場所は、はじめの 1 回だけ選ぶ（次からは覚えている）。
3. 「登録」。前に誰かが登録していたら、どこから何 km・何時間で来たかが出る。いなければ、このお札の旅の出発点になる。
4. 番号が珍しければ（ゾロ目・キリ番・若い番号・階段・鏡・くり返し・ぞろぞろ・英字もそろう）、その場で分かる。
5. 人にお札を渡すときは、結果の画面から「リレーのリンクを送る」。相手が開くと記番号・券種が入った状態で、場所を確かめて登録するだけでつながる。
6. 券種のボタンの右「もっと見る」から、今は発行していないが法的に有効な古いお札（一万円〜五十円、A 号券より前を除く）も選べる。肖像の人物名と発行年から選ぶ（形だけでは号券を決められないため）。

お札への書き込み・スタンプはしない（貨幣損傷等取締法は硬貨だけが対象だが、日銀は大切に扱うよう求めている。書き込みのあるお札は ATM・自販機で通らないことがある）。

下のタブ: 「登録」「自分の記録」（まとめ・自分の地図・レア番号の図鑑・一覧）「みんな」（登録した場所の地図・再発見の旅・絞り込み、記番号は出さない）。

### Firebase の準備（オーナーが Firebase コンソールで行う）

このアプリの共有部分（他人との記番号の照合・みんなの画面・リレーのリンクでのつながり）は
Firebase（Spark プラン・無料）を使う。`firebase-config.js` が `null` のままだと、登録・道のり・
みんなの画面は「準備中」を出し、それ以外（キーパッド・カメラでの読み取り・レア番号の判定・
自分の記録の端末内の部分）は今までどおり動く。

1. [Firebase コンソール](https://console.firebase.google.com/) で新しいプロジェクトを作る（案: `tof-shihei-relay`。Google アナリティクスはオフでよい。hue-hunter とは別のプロジェクト）。
2. **Authentication** → Sign-in method → **匿名** を有効にする。**設定 → 承認済みドメイン** に、公開する Cloudflare の Workers ドメイン（`shihei-relay.<アカウント名>.workers.dev`）と `localhost` を追加する。
3. **Firestore Database** を作成する。ロケーションは **`asia-northeast1`（東京）**、本番モードで開始する。
4. 「アプリを追加」→ ウェブアプリを登録し、出てきた `firebaseConfig` の値を `firebase-config.js` の `window.SHIHEI_FIREBASE_CONFIG` にそのまま入れる（`apiKey` は公開してよい値。守りは `firestore.rules` 側）。
5. Firestore の「ルール」タブに、このリポジトリの [`firestore.rules`](firestore.rules) の中身を貼り付けて **公開** する。**`firestore.rules` を直すたびに、ここへ貼り直して公開しないと本番に効かない。**
6. **公開前に** App Check（reCAPTCHA v3）を有効にする（無料の Spark プランのまま、ボットによる読み取り連打から無料枠を守るため）。
   1. [reCAPTCHA の管理画面](https://www.google.com/recaptcha/admin/create) で **v3** のキーを作る（ドメインに `shihei-relay.t-of.workers.dev` と `localhost` を追加）。
   2. Firebase コンソール → **App Check** → ウェブアプリを登録し、プロバイダを **reCAPTCHA v3**、上で作ったサイトキーを入れる。
   3. 出てきたサイトキーを `firebase-config.js` の `appCheckSiteKey` に入れる。
   4. 数日〜1 週間ほど「指標」タブで、正当なリクエストの割合を見る（低すぎると本物の利用者まで弾く）。
   5. 割合が十分に高いことを確かめてから、Firestore・Authentication それぞれの App Check 設定を「モニタリングのみ」から **「適用」** に切り替える。

エミュレーターは入れていない（Java と npm が要るため。RULES 同様、実装担当が本番のプロジェクトで
手で確かめる）。公開後、次を手で確かめて結果をここに書き足すこと。

- [ ] 形の悪い記番号（キーで打てない形でも、リレーのリンクを細工すれば送れるため）が `sightings` の書き込みで拒まれる
- [ ] 同じお札を 30 秒以内にもう一度登録すると拒まれる
- [ ] 同じお札の 2 回目（別の人・30 秒後）は書ける
- [ ] 他人の `sightings` を消そうとすると拒まれる（自分の分は消せる）
- [ ] `hits` の一覧が 50 件を超えて読めない・形の範囲外の書き込みが拒まれる
- [ ] 昔のお札の鍵（`B500K-A123456B` など）が書ける
- [ ] 号券・色の組み合わせが違う鍵（`C10000B-A123456B`・`B50K-AB123456C` など）は拒まれる

**「みんなの地図」の集計（`agg/{id}`。仕様「21」）を有効にするとき**、次も確かめて結果をここに書き足すこと
（`firebase-config.js` の `window.SHIHEI_AGG_ENABLED` を `true` にする前に、rules を公開してから）。

- [ ] ふつうの登録で `agg/all`・その日の `agg/d<年>-<月>-<日>` のセルがちょうど 1 増える
- [ ] sighting を作らず（別の書き込みだけで）`agg` を増やそうとすると拒まれる
- [ ] 1 回の登録でセルを 2 増やそう・別の市区町村を増やそうとすると拒まれる
- [ ] 昨日の `agg/d…` を増やそうとすると拒まれる
- [ ] `agg` を消そう・`list` で読もうとすると拒まれる（`get` は誰でもできる）
- [ ] `limit(51)` の `hits` の一覧が拒まれる（50 まで）
- [ ] うその `ty`（登録した鍵と違う号券）を付けた `hits` が拒まれる

有効にしたら、次の手順で出す（ディレクター経由。仕様「21-10」）。

1. ディレクターが新しい `firestore.rules` の中身をオーナーに渡し、オーナーが Firebase コンソールで **公開**（上の 5 と同じ手順）。
2. オーナーが Firestore → インデックス → 単一フィールド → 除外を追加: コレクション `agg`、フィールド `m`（昇順・降順・配列をすべて切る）。`m` はネストしたマップで市区町村・号券の組み合わせぶん索引が作られてしまうため。
3. 上のチェックリストを本番で確かめる。
4. `firebase-config.js` の `window.SHIHEI_AGG_ENABLED` を `true` にして出す。

読み取り回数の見積り（仕様「21-5」の 1 回のバッチにつき 20 回までの上限）: `agg` の書き込みルール（`isCountUp`）と
`hits` の `ty` の確かめは、どちらも `users/{uid}` と今回の `sightings` の文書を `get`/`getAfter` する。
同じ文書への 2 回目以降の呼び出しは Firestore 側でキャッシュされ、上限には数えられない
（[公式ドキュメント](https://firebase.google.com/docs/firestore/security/rules-conditions#access_other_documents)）ため、
実際に数えられる呼び出しは少数（`users/{uid}` と対象の `sightings` 文書だけ）で収まる見込みだが、
本番のプロジェクトでの実測はしていない。詰まる（`resource-exhausted` や想定外の `permission-denied`）ようなら、
`isCountUp` を `agg/d…` 側だけ「`agg/all` の同じセルが +1 されている」と比べる形に減らす（仕様「21-5」の代案）。

## カメラで記番号を読む（Tesseract.js）

[Tesseract.js](https://github.com/naptha/tesseract.js)（7.0.0）と
[tesseract.js-core](https://www.npmjs.com/package/tesseract.js-core)（7.0.0、LSTM 専用のコアだけ）を
`vendor/tesseract/` に同梱し、外部 CDN からは読まない。カメラのボタンを初めて押したときだけ読み込む
（写真はどこにも送らない・保存しない。README「プライバシー」参照）。

| ファイル | 大きさ |
|---|---|
| `tesseract.min.js` + `worker.min.js` | 約 0.17 MB |
| `tesseract-core-simd-lstm.wasm.js`（Safari 16.4 以上・大半の端末） | 約 3.9 MB |
| `tesseract-core-lstm.wasm.js`（simd 非対応の古い端末向け） | 約 3.9 MB |
| `tesseract-core-relaxedsimd-lstm.wasm.js`（対応端末向け、より速い） | 約 3.9 MB |
| `eng.traineddata.gz`（`tessdata_fast`、英数字の学習データ） | 約 1.9 MB |

**1 回のカメラ利用で実際にダウンロードされるのはコア 1 種類だけ**（`wasm-feature-detect` が端末に
合わせて 3 つから 1 つを選ぶ）ので、初回の実測は **本体・作業用スクリプト（0.17MB）+ コア 1 つ（約 3.9MB）
+ 学習データ（約 1.9MB）= 約 6MB** になる見込み（仕様の見積り 5〜9MB に収まる）。2 回目からは
Service Worker のキャッシュ（`shihei-relay-ocr-v1`）から読むので通信は発生しない。

**実機での読み取り精度・速度（iPhone Safari、本物のお札 10 枚）は未計測。** このアプリの実装は
テキストのみの環境で行ったため、カメラと実物のお札を使う確認ができなかった。次の担当が実機で
確かめ、10 枚のうち何枚が直さずに合うか・1 回の読みにかかる時間をここに書き足すこと
（7 枚を下回るなら、切り抜き・二値化の閾値を見直すか、`tesseract-wasm` への切り替えを検討する）。

## データ

### 端末の中（localStorage）

| キー | 中身 |
|---|---|
| `shihei-relay.settings` | `{ v: 1, sound: true, input: 'pad' \| 'camera', lastDenom: 10000\|null, lastMuni: '13101'\|null, guided: 0, listSort: 'new'\|'old'\|'num'\|'rare'\|'far', listFilter: 'all'\|'fav'\|'rare', lastNoteType: 'D1000'\|…\|null }`。`confirm`（登録前の確かめのスキップ）は廃止した。確かめは必ず出すので、古いデータに残っていても読み捨てるだけでよい。`listSort`・`listFilter`・`lastNoteType` は「一覧」「昔のお札」（18・19 節）で足した項目。表にない値は初期値（`'new'`・`'all'`・`null`）に戻す |
| `shihei-relay.mine` | `{ v: 1, bills: [{ key, muni, at, seen, rare: string[], km, comebacks: 0, fav: true }] }`。自分が登録したお札（最大 1,000 件、お気に入りは超えても優先して残す）。`km` はこの端末からの登録で分かった移動距離の合計、`comebacks` は「戻ってきた」を選んで登録した回数（無い古いデータは 0 として読む）。`fav` はお気に入りのときだけ付く（端末の中だけ）。レアの印は保存せず、一覧に出すたびに `key` から計算する |
| `shihei-relay.dex` | `{ v: 1, found: { zorome: 1790000000000, …, kaiki: …, mukashi: … } }`。レア番号の図鑑（初めて当てた時刻）。`kaiki` は「戻ってきたお札」、`mukashi` は「昔のお札」に初めて出会った時刻（どちらもレア番号と同じ図鑑の枠に並ぶ） |

読み書きは try/catch で囲む。写真は保存しない（localStorage にも IndexedDB にも入れない）。
文字を読む部品は Service Worker のキャッシュ `shihei-relay-ocr-v1` に入る（2 回目からは読み込まない）。

#### 端末をまたいだ記録の書き出し・読み込み（機種変更・アプリの入れ直し対策）

設定画面「記録を書き出す」で、上の 3 つのキー（`mine`・`dex`・`settings`）を 1 つの JSON ファイルに
まとめて書き出せる。ファイル名は `shihei-relay-YYYYMMDD.json`。

```json
{ "app": "shihei-relay", "v": 1, "exportedAt": 1790000000000, "mine": { "v": 1, "bills": [...] }, "dex": { "v": 1, "found": {...} }, "settings": {...} }
```

iOS のホーム画面アプリではダウンロードが効かないことがあるため、`navigator.canShare({ files })` が
使えるときは共有シートを、使えなければ `<a download>` でのファイル保存を使う。

「記録を読み込む」で選んだファイルは、**今の端末のデータを上書きせず足し合わせる**（`js/bill.js` の
`parseImportPayload`・`mergeBills`・`mergeDexFound`。node --test で確認済み）。

- 読み込む前に、ファイルの形（`app` が `shihei-relay`・`v` が知っている値）と、`bills` の各行（`key` が
  `parseKey` を通る・`muni` が `isMuniCode` を通る・`at` が数）を確かめる。合わない行・ファイルは黙って
  捨て、形自体が違えば何も変えずにトーストで知らせる。
- `mine.bills`: 同じ `key` は、`seen`・`km`・`comebacks` は大きい方、`at` は早い方（旅の始まりを残す）、
  `fav` はどちらかに付いていれば付ける。足し合わせたあとも 1,000 件の上限とお気に入りの優先は
  変わらない（`trimBills`）。
- `dex.found`: 同じ図鑑の枠は早い時刻の方を残す。
- `settings`: 読み込まない（今の端末の設定をそのまま使う）。

サーバー（Firestore）側の登録は引き継げない。匿名 id は端末ごとに違うため、前の端末で登録した
`sightings` を新しい端末から消すことはできない（自分の記録・図鑑は上のとおり引き継げる）。

一覧（自分の記録の「記録を見る」）は別画面にせず、券種ごとにまとめて開閉し、しぼり込み（すべて／お気に入り／レア）・
並び替え（新しい順・古い順・番号順・レア順・距離の長い順）・お気に入りの★ができる。Firestore には聞きに行かず、
端末の `mine` だけで描くので圏外でも出る（`js/bill.js` の `parseKey`・`compareBills`・`RARE_RANK`）。

### 端末の外（Firestore）

お札の鍵 `key` = `<号券><券種><色>-<記番号>`。例 `F10000K-AB123456CD`（新しい 1 万円・黒）、
`D1000G-AB123456C`（昔の千円・夏目漱石・緑）。色は K 黒 / B 茶（褐色）/ N 紺 / U 青 / G 緑。
号券・券種・色・記番号の形の組み合わせは `js/bill.js` の `NOTE_TYPES` に 1 つだけ置いてある
（今の 1 万・5 千・千・2 千円に、今は発行していないが法的に有効な一万円〜五十円を「もっと見る」として足したもの。
A 号券とそれより古いお札は形が違うため対象外）。

**`bills/{key}/sightings/{docId}`** — 1 回の登録が 1 件。文書の id は、最初の登録が `{uid}`
（登録した人の匿名 id）、**戻ってきたとき（2 件目以降）は `{uid}_{n}`（n は 1〜3）**。
1 人が 1 枚のお札に書けるのは、これで最大 4 件（n=0〜3）まで。同じ人がまた登録しようとしたときの
「また手元に来ましたか？」の判定は `js/bill.js` の `analyzeRegistration`（node --test で確認済み）。

| 項目 | 型・範囲 | 説明 |
|---|---|---|
| `muni` | string、5 桁の数字、頭 2 桁が 01〜47 | 市区町村（全国地方公共団体コードの頭 5 桁） |
| `at` | timestamp、`request.time` のみ | 登録の日時 |
| `v` | 1 | 版 |

- 前の自分の登録から **3 時間**（`Bill.RETURN_MIN_GAP_MS`）あいていないと、次の登録を「持ち歩いた」「戻ってきた」
  として選べない（重ねて押した・同じ登録の取り違えを防ぐ）。
- 同じ人がまた登録しようとしたときは「今回は、前の登録からどう動きましたか？」を聞く（`js/app.js` の
  `#ask-return-sheet`）。sightings の文書はどちらを選んでも同じように書くが、扱いが違う。
  - **持ち歩いて移動した**（`confirmedReturn: 'carried'`）: ずっと自分が持っていたので、`hits` には書かない・
    comeback 扱いにもしない（みんなの一致の記録・図鑑の「戻ってきたお札」に載せない）。結果画面には
    前の自分の登録からの距離・経過時間だけを出す。
  - **人の手を渡って戻ってきた**（`confirmedReturn: 'returned'`）: 今までどおり `hits` に comeback として書き、
    図鑑の「戻ってきたお札」に数える。間にほかの人の登録があってもなくても選べる
    （紙幣リレーを使っていない人の手を渡って戻ってくることがあるため）。

**`hits/{autoId}`** — 再発見 1 回の知らせ（みんなの画面用）。記番号を持たない。

| 項目 | 型・範囲 | 説明 |
|---|---|---|
| `denom` | 50 / 100 / 500 / 1000 / 2000 / 5000 / 10000 | 券種 |
| `from` / `to` | string、5 桁の市区町村コード | 前の登録といまの登録の市区町村 |
| `km` | int、0〜3000 | 距離 |
| `mins` | int、0 以上 | かかった時間（分） |
| `n` | int、2〜1000 | 何人目か（`sightings` の一覧は 100 件までしか読めないので、100 人を超えたお札は頭打ちになる） |
| `comeback` | bool | 自分のところへ戻ってきた登録なら true（みんなの画面で 🔁 の印） |
| `ty` | string、NOTE_TYPES の id（例 `F10000`）。無くてもよい | 号券+券種（仕様「21」。AGG_ENABLED のときだけ付く。無い hits は「みんなの地図」の新・旧・昔の絞り込みでは出ない） |
| `at` | timestamp | |
| `v` | 1 | |

**`agg/{id}`** — みんなの地図（仕様「21」）の集計。記番号を持たない。`id` は `all`（ずっとの合計）か
`d<年>-<月>-<日>`（日本時間のその日、0 を詰めない。例 `d2026-9-27`）。

| 項目 | 型・範囲 | 説明 |
|---|---|---|
| `m` | `{ 市区町村コード: { typeId: int } }` | 市区町村ごとの、号券+券種（`NOTE_TYPES` の id）ごとの登録の回数。持ち歩き・戻ってきたも +1（登録の回数として数える）。自分の登録を消しても減らない |
| `v` | 1 | |

- 増やすのは `increment(1)`（読まずに書ける）。誰でも `get` できる（`list` はできない＝全市区町村を一度に読む手段はないが、地図には `all`・日ごとの文書を直接 `get` するので支障ない）。
- `firebase-config.js` の `window.SHIHEI_AGG_ENABLED` が `true` のときだけ、登録のたびに `agg/all` と今日の `agg/d…` の該当セルを +1 する（既定は `false`。上の「Firebase の準備」に手順）。

**`users/{uid}`** — `{ last: timestamp, since: timestamp, n: int, v: 1, b?: string, s?: string }`。最後に登録した時刻と、`since` から 24 時間の登録数（いたずらの歯止め）。`b`（今回登録した鍵）・`s`（今回の sighting の文書 id）は AGG_ENABLED のときだけ付き、`agg` の書き込みが「同じバッチの新しい登録の分だけ」であることを rules が確かめる手がかりに使う（本人しか読めないので、記番号は公開されない）。本人だけが読み書き。

- 読む: `sightings` はその `key` を知っている人だけ（bills 全体の一覧・sightings のコレクショングループ検索はできない）。`hits` は誰でも新しい順に 50 件まで。`agg` は誰でも `get` できる。
- 書く: ログインしている本人だけ。書き換えはできない。消せるのは自分の `sightings` だけ（`agg` は増やすだけで、減らす・消す操作は無い）。
- 形を確かめているのは [`firestore.rules`](firestore.rules)。ここを変えたら、この表・`js/firebase.js`・ルールを同じコミットで直し、Firebase に公開し直す。

### 市区町村の表（`data/muni.json`）

出典: [jp-address-search](https://github.com/uiuifree/rust-jp-address-search)（MIT License, © uiuifree）に
同梱されている、総務省・国土交通省の公開データ由来の市区町村マスタと本庁舎緯度経度から作成。
政令指定都市の行政区は市にまとめてある（例: 札幌市中央区 → 札幌市）。1,741 件（北方領土の
色丹村・泊村・留夜別村・留別村・紗那村・蘂取村は本庁舎の位置データが無いため含まない）。
よみ（ひらがな）は元データに無いため持たない。市区町村名を打って探す画面は、漢字の部分一致で
候補を絞る（`js/geo.js` の `searchMuni`）。

### 日本の輪郭（`data/japan.svg`）

出典: [Natural Earth](https://www.naturalearthdata.com/)（パブリックドメイン、著作権表示不要）の
1:50,000,000 の国境データから日本の部分を取り出し、Douglas-Peucker 法で間引き、小さすぎる離島を省いた
もの。緯度経度→画面座標の変換は `js/geo.js` の `project()`（等長円筒図法に緯度 36° の cos 補正を掛けた簡易投影）。

## プライバシー

- カメラの映像は端末の中で文字を読むためだけに使い、送らず、残しません。撮影の画面を閉じるとカメラを止めます。
- 写真はどこにも保存しません。
- 登録した市区町村と日時は、そのお札の記番号を知っている人（= そのお札を手にした人）にだけ見えます。登録した人が誰かは分かりません。

## 実装からの申し送り（仕様から外した・簡略化した点）

このアプリは、実機のお札・iPhone・Firebase プロジェクトのいずれも使えないテキストのみの環境で
実装した。次のとおり、いくつかの点を仕様よりも簡略にしている。

- **キーパッドの「次に来る文字」の自動出し分け**（英字 24 文字・数字 10 文字を記番号の位置に応じて
  出し分ける）は実装していない。すべての 34 文字を常に出し、形が合ったら「登録」を押せるようにする
  だけにした（打ち間違いの形は作れる点だけ仕様と異なる。形が合わなければ登録できないので実害は小さい）。
- **記番号の枠の数**は号券が確定するまで最大の 10（F 号券の形）で固定表示し、確定後に区切りだけ入れる。
  E・D 号券（末尾 1 文字）の枠の数がその場で減る演出は入れていない。
- **「みんな」の登録総数**は、AGG_ENABLED が `false` の間（rules 公開前）は記番号を伏せた設計上
  どのお札にも横断してアクセスする手段がなく出せない。AGG_ENABLED を `true` にしたあとは
  `agg/all` から出す（仕様「21」）。
- **自分のお札が旅した合計 km・新しい動きの検知**は、この端末で登録した瞬間に分かった分だけを積算する
  （他の人が動かした分をポーリングして拾いには行かない）。
- **写真を選んで読む**（カメラの無い環境向け）は、四角を指で動かして記番号に合わせる操作を省き、
  選んだ画像全体を読む簡易版にした。
- Tesseract.js の実機での読み取り精度・速度は未計測（上の「カメラで記番号を読む」を参照）。
- Firestore のセキュリティルールは、Firebase プロジェクトが無いため本番での手動確認ができていない
  （上の「Firebase の準備」のチェックリストが未了）。
- **みんなの地図（仕様「21」）**: rules がまだ公開されていない本番で書き込みが失敗しないよう、
  `firebase-config.js` の `window.SHIHEI_AGG_ENABLED`（既定 `false`）で agg の書き込み・地図の集計表示を
  まとめて止められるようにした（下の「みんなの地図の集計を有効にする」参照）。地図の点のタップ判定は
  ズームしても一定の大きさ（見た目の 44px 相当）を保つが、画面上のピクセル距離での厳密な計測はしていない。
  「今週」の代わりに「7 日間」（今日を含む直近 7×24 時間、または暦日 7 日分）にした（オーナーの決定どおり）。
  hits の期間・お札・距離・種類の絞り込みは、最新 50 件を読んだ結果を端末の中で絞り込む
  （仕様は期間ごとに読み直す想定だったが、Firestore の読み取り回数を増やさず同じ 50 件から絞れるので、
  この形にした）。番号（レア番号）の絞り込みは仕様どおりあとに回した。
